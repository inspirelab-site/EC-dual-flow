# Response to Reviewer 3TGk’s Follow-up Comment 2

We thank the reviewer for emphasizing this issue and apologize that our previous runtime report did not distinguish isolated pairwise latency from attainable workload throughput.

**Runtime clarification and throughput benchmark.** The previously reported 110.4±161.3s per directed pair was measured sequentially, with only one pair evaluated at a time. It therefore reflects isolated latency on a substantially underutilized L40S GPU—mean utilization was approximately 6.5%—rather than attainable workload throughput. Total wall time should not be estimated simply as N(N−1) times this latency because independent pair evaluations can run concurrently on the same GPU.

We benchmarked throughput using the same Dual-flow implementation, with MATLAB’s dlaccelerate enabled and multiple pair evaluations scheduled concurrently. The workloads comprised 44 Rat BOLD evaluations (22 scans × 2 directed pairs) and 900 Mod10 evaluations (10 realizations × 90 directed pairs from the simulated two-module network; see Table Y). The concurrency setting was optimized on 1×L40S and applied unchanged to each GPU in the 4×L40S configuration. Each optimized configuration was repeated five times using matched pair-level seeds. We standardized the benchmarks at T=256, as prior sensitivity analysis showed that mean capacity estimates varied by at most 4.30% across $T\in${256, 512, 1024, 2048, 4096}.

Throughput-benchmark values are mean ± SD across five repetitions; the sequential Rat benchmark was rerun under the original sequential settings. In one seed-matched Rat comparison, the throughput configuration reduced wall time from 6107 to 528s, corresponding to an 11.6-fold increase in single-GPU throughput. The small Rat workload benefited little from 4×L40S GPUs because overhead dominated, whereas Mod10 achieved a 3.7-fold speedup and 92.46% parallel efficiency, reducing evaluation of all 90 directed pairs from 7.85 to 2.12 min. These execution changes reduce wall time through improved hardware utilization but do not reduce the underlying computational work.

**Acknowledged limitation and practical scope.** We agree that improved hardware utilization does not alter the underlying computational burden. As acknowledged in the original submission, computational cost limits scalability to larger analyses. The new benchmarks clarify the intended practical scope of the current implementation: focused analysis of prespecified circuits and moderately sized subnetworks rather than unrestricted whole-brain analysis. We will revise the Conclusion and Limitations accordingly.

**Scientific value of focused EC analysis.** We agree that scalable whole-brain causal discovery is an important methodological objective. In parallel, EC analysis of prespecified circuits and subnetworks is an established use case with broad practical utility in neuroimaging. Smith et al. (Frontiers in Systems Neuroscience, 2012) note that effective connections are often estimated among a small number of task-relevant ROIs. Deshpande and Hu (Brain Connectivity, 2012) distinguish confirmatory circuit analysis from exploratory network discovery. Methodological reviews similarly distinguish hypothesis-driven analysis of predefined subnetworks from unrestricted whole-brain exploration (Bielczyk et al., Network Neuroscience, 2019; Rossini et al., Clinical Neurophysiology, 2019). Our empirical experiment follows this hypothesis-driven design: four tongue-motion ROIs were predefined using task-activation maps, yielding 12 directed pairs.

Dual-flow models the empirical residual distribution and iteratively optimizes the input distribution for each directed pair. In our controlled experiments, this richer modeling produced substantially stronger overall directed-edge recovery at greater computational cost, illustrating a statistical-performance–computational-efficiency trade-off. Thus, the current implementation supports focused EC analysis of prespecified circuits and moderately sized subnetworks, while unrestricted whole-brain deployment remains a direction for future computational optimization.
